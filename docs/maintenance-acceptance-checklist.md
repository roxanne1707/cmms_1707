## 手动复验

1. 使用测试凭据访问 3289 或 3389，确认仪表详情、设备概览、维修台账与通知页面。不要使用原部署数据做写入验证。
2. 在具有合法权限/许可的测试数据上检查策略与等待；如没有对应授权，用已提供的前端脚本及真实 JPA 集成测试复验，不能修改许可证校验。
3. 运行两套完整回归，分别生成带时间的脱敏统计；同一套测试不可跨轮相加。
4. 打包并验证新 JAR，再按文档启动实验 API；原部署端口与进程保持不动。
5. 以独立监控凭据检查 Actuator；匿名请求被拒绝，监控持续抓取不再占业务限流额度。不要把故意触发的 429 当作服务宕机。
6. 复验远端 CI/容器请按 [补充验收](maintenance-remote-verification.md) 触发两条功能分支工作流；实际外发须先准备专用测试账号和接收端。
